# Admin integration status and future work

The earlier roadmap in this file has been implemented as a separate Next.js application in `apps/admin`, deployed at `https://fashion-feet-admin.vercel.app`. It shares Neon PostgreSQL with the public storefront. The admin has its own login, TOTP MFA, roles, audit views, product/collection/category/store/FAQ managers, media library, seasonal controls, and Storefront Studio. See [AdminDeployment.md](AdminDeployment.md) for security and deployment details.

Storefront content is updated through the shared database. Draft Studio changes require publication, and open storefront tabs need a refresh. The FAQ manager edits the same rows rendered by `/faq` and `/api/v1/faqs`.

Remaining integration work is operational. The `fashionfeet.co.in` DNS step is finished: the GoDaddy apex A record was added on 10 November 2026 and the hostname verified and served over HTTPS the same day. The storefront's production `AUTH_URL`, `NEXTAUTH_URL`, and the admin project's `NEXT_PUBLIC_STOREFRONT_URL` were then updated from the Vercel alias to `https://fashionfeet.co.in`; measured on 10 November the deployed storefront still advertised alias-based NextAuth callback URLs, because deployment environments are snapshotted and Vercel requires a new production deployment to apply them. That redeploy is gated by Vercel's email OTP step-up challenge on deployment creation, so it must be run by the account owner (dashboard Redeploy, or their normal `vercel deploy --prod`). After it lands, re-verify `/api/auth/providers` on the custom hostname, submit one live enquiry, and confirm inbox arrival. Formspree now sends enquiry notifications to `aryan.kapoor@fashionfeet.co.in`; a live delivery test succeeded on 6 November 2026. The direct Resend account is optional and would still need DNS verification if used later. The native mobile app also needs a release pipeline and store distribution before it can be treated as a shipped client.
