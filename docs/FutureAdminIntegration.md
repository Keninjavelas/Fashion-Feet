# Admin integration status and future work

The earlier roadmap in this file has been implemented as a separate Next.js application in `apps/admin`, deployed at `https://fashion-feet-admin.vercel.app`. It shares Neon PostgreSQL with the public storefront. The admin has its own login, TOTP MFA, roles, audit views, product/collection/category/store/FAQ managers, media library, seasonal controls, and Storefront Studio. See [AdminDeployment.md](AdminDeployment.md) for security and deployment details.

Storefront content is updated through the shared database. Draft Studio changes require publication, and open storefront tabs need a refresh. The FAQ manager edits the same rows rendered by `/faq` and `/api/v1/faqs`.

Remaining integration work is operational. The `fashionfeet.co.in` DNS step is finished: the GoDaddy apex A record was added on 10 November 2026 and the hostname verified and served over HTTPS the same day. The storefront's production `AUTH_URL` and `NEXTAUTH_URL` were then updated from the Vercel alias to `https://fashionfeet.co.in`. Deployment environments are snapshotted, so the change only applied once the account owner passed Vercel's email step-up challenge and a new storefront production deployment landed on 10 November. Re-measured after it: `/api/auth/providers`, the `/api/auth/csrf` callback cookie, and the `/api/auth/signin` redirect all return the custom hostname, `/sitemap.xml`, `/robots.txt`, and the Open Graph URLs are published on it, and a live contact submission through `https://fashionfeet.co.in/contact` returned the storefront's success state, meaning Formspree accepted the notification; only inbox confirmation by the owner remains. Formspree has sent enquiry notifications to `aryan.kapoor@fashionfeet.co.in` since a first successful delivery test on 6 November 2026. The admin project still runs its 2 November deployment, where an attempted "use existing files" redeploy failed with `NOW_SANDBOX_WORKER_ROOTDIR_NOT_EXIST`; its corrected `NEXT_PUBLIC_STOREFRONT_URL` therefore applies at the next admin release, and nothing in the production admin path currently reads that variable because uploads use Vercel Blob. The direct Resend account is optional and would still need DNS verification if used later. The native mobile app also needs a release pipeline and store distribution before it can be treated as a shipped client.
