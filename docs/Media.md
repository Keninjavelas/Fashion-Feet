# Media and brand assets

The production admin upload endpoint lives only in `apps/admin` and uses Vercel Blob. The shared `MediaAsset` table stores asset metadata and URLs. `src/lib/media.ts` resolves published assets and identifies where a URL is used before replacement or deletion. An upload alone does not place an image on a public page; a published product, collection, festival, setting, or Studio section must reference it.

The official brand logo is checked into `public/branding/fashion-feet-official.png` and rendered by `BrandLogo`. Two user-supplied past-exhibition photographs are checked into `public/exhibitions/` and rendered by `PastExhibitions`. These are authentic exhibition images; do not substitute them for product-specific catalogue photography.

The owner supplied 21 women's footwear photographs on the Desktop, labelled `w daily`, `w fest`, and `w c`. Original copies are preserved in the ignored `intake/products/women/` folders; checked-in copies are in `public/catalogue/women/{daily-wear,festive,ceremonial}/`. The Desktop source files were removed after hash verification at the owner's request.

Seven more original photographs, labelled `f u 1` through `f u 7`, were moved from the Desktop into `public/catalogue/women/rajwadi/` and hash verified. These show toe-loop sandals, including two colour variants together in photograph 03. The separate Desktop image `f unique` names the group **MTR Rajwadi Collection**; a copy is stored in `docs/references/rajwadi-category.jpeg` solely as the category reference. It is not displayed on the storefront because it carries separate branding. The storefront uses **Rajwadi** for this women-only group. The reference is not evidence of prices, materials, sizes, or stock.

`WomenCatalogueGallery` shows studio-style transparent-background derivatives from `public/catalogue/women/studio/` on `/women` and the matching women's `/shop` views while there are no published products. Daily Wear previews use `studio/daily-wear/`; Festive uses `studio/festive-v2/`; Ceremonial photos 02–04 use `studio/ceremonial-v2/`, while revised photos 01 and 05 use `studio/ceremonial-v3/`; Rajwadi uses `studio/rajwadi/`. The previews share a fixed square frame and warm neutral background. Edited previews may differ in details from the source photos, so every preview links to its unedited original. Display names in `WomenCatalogueGallery` are editorial names based on appearance, not confirmed product names or records in the admin catalogue. Festive photo 7 is identical to Festive photo 5 and displays once. Ceremonial photo 1 and Festive photo 1 share one original, use the same display name, and have distinct preview arrangements. Ceremonial photo 5 is only a close-up in its source; its full-pair preview reconstructs missing areas and is explicitly labelled as such. Confirm its inferred details against a full original before using it as a product listing. Prices, materials, sizes, and availability are not inferred from these images.

The Desktop file `mens.jpeg` contains **five** distinct embroidered men's juttis, despite the initial description of four. It was copied without altering the Desktop file to `public/catalogue/men/functional/group.jpeg`; the two copies have matching SHA-256 hashes. `MenCatalogueGallery` shows five transparent, studio-style individual cutouts from `public/catalogue/men/studio/functional/`, one for each visible shoe. Future men's Daily Wear, Festive, and Ceremonial photographs should follow the same square frame and source-link practice. Do not infer prices, materials, sizes, or availability from photographs.

Local SQLite development can use local uploads, but production must retain the Blob integration and its `BLOB_READ_WRITE_TOKEN` on the admin Vercel project. Never commit upload credentials or user-uploaded media from the local `public/uploads/` directory.
